Modelagem de Dados

11 tabelas — decisões importantes

🔐
Usuario + Cliente separados
Credenciais de acesso (email, senha) separadas dos dados comerciais. Permite LGPD sem quebrar histórico.
💸
TransacaoFinanceira central
Receitas (vendas) e Despesas (compras, avulsas) em uma única tabela. Simplifica o Dashboard e Fluxo de Caixa.
🗑️
Soft Delete (deleted_at)
Nada é apagado fisicamente. Registros são marcados com a data de exclusão. Histórico preservado para sempre.
📋
LogsAuditoria automática
Toda ação relevante (atualizar pedido, excluir dados) registra quem fez, o quê e quando.

O que foi difícil

Dificuldades reais do projeto

🤝
Alinhamento com a cliente
A Cleonice sabia o que queria no geral, mas na hora de detalhar surgiam novas necessidades: "e se eu quiser ver as clientes que fazem aniversário?", "mas como eu calculo o preço das peças?". A maior dificuldade foi fazer as perguntas certas para entender o que ela realmente precisava, não apenas o que descrevia. Aprendemos que o cliente descreve o problema, mas não a solução.
🌐
Fazer os servidores se "enxergarem"
O Supabase usa IPv6 e o Render só aceita IPv4. Ficamos horas tentando entender por que a conexão falhava sem dar uma mensagem clara. A solução foi usar o "Session Pooler" do Supabase, que é um caminho compatível com IPv4. Parecia mágica quando funcionou.
⚖️
Escopo que cresce conforme o projeto evolui
Começamos com o básico e fomos adicionando funcionalidades ao longo do semestre. Cada semana uma ideia nova surgia — fotos dos produtos, aniversário das clientes, histórico de pedidos. Organizar o que ficaria para depois e o que entrava agora foi um desafio constante de gestão.
